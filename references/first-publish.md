## 一、先决定默认分支叫什么

**在第一次提交之前定下来**，之后改要动远端默认分支、本地跟踪关系、以及所有文档里的分支名。

```
git init -b main
```

`-b` 在较老的 git 上不可用，退路是先 `git init` 再 `git symbolic-ref HEAD refs/heads/main`。
**别等推上去再改名** —— 远端默认分支改名会让旧链接与本地跟踪关系一起错位。

## 二、建远端的三条路径

| 路径 | 适用 | 要注意 |
|---|---|---|
| 平台网页上手动新建 | 任何情况 | 建完**不要**勾「自动创建 README / .gitignore / LICENSE」—— 会造出一个与本地无关的提交，首次推送直接变成「历史不相关」 |
| 官方命令行工具 `gh repo create` | 运行环境里装了这个工具 | 同样注意别初始化出多余提交；一步到位建仓 + 设远端 + 首次推送 |
| 先有远端空仓库，再在本地加远端 | 远端由别人建好 | `git remote add origin <URL>`，再确认远端确实是空的（`git ls-remote <URL>` 返回空） |

**判据**：远端是不是空的，用 `git ls-remote <URL>` 看有没有输出。
**不为空又非快进关系时不要硬推** —— 先搞清楚那个提交是谁的。

> 三条路径都在**执行环境**里做，涉及网络与凭据；
> 通路问题按主文件的阶段 3 分层判定，别在这里现猜。

## 三、把仓库的「门面」配齐

这些项**不影响功能，但影响别人怎么判断这个仓库**，发布后顺手就配：

| 项 | 为什么 |
|---|---|
| **可见性**（公开 / 私有） | 决定了「读接口是否需要认证」「能不能免认证回验」。**发布前确认一次，别事后才发现搞反了** |
| **许可** | 仓库里的 `LICENSE` 文件与门面上选定的许可要一致；不一致时别人不知道按哪个用 |
| **主题标签** | 决定这个仓库能不能被搜索到。选 5–10 个准确的、别堆砌 |
| **简介** | 一句话说清「这是什么、给谁用」 |
| **官网 / 相关链接** | 有文档站或发布页就填上 |

⚠️ **许可一旦发布再改，要同时改文件与门面，并且旧版本里那份仍是旧的** ——
所以「用哪个许可」最好在首次发布前就想清楚。

## 四、身份：提交邮箱决定贡献图

提交里的作者邮箱，决定了这次提交算在哪个账号的贡献记录上。

- **想让它计入贡献记录**：用平台提供的**专用免回复邮箱**，且必须带**数字账号 ID**
  的那种形态。不带 ID 的写法语法上合法，但**不计入贡献图** —— 这个差别很隐蔽。
- **不想暴露真实邮箱**：就是上面这种专用邮箱的用途。
- **邮箱写错了不会报错**，只是贡献记录落到别处（或没有）。所以**首次提交后回看一眼**。

两处都要设，缺一处会出现「作者对了、提交者不对」：

```
git config user.name  "<名称>"
git config user.email "<专用免回复邮箱>"
```

写**仓库级**配置（不加 `--global`）—— 换一个项目就可能换一个身份。
但要记得：**脚本逐版重建历史时不写仓库级身份，事后手工 `amend` 会报身份未知**，
所以重建脚本里也要带一遍。

> **凡是会被填进 URL 的标识必须是纯 ASCII。** 显示名可以是中文，
> 但它不能拿来当账号名 —— 中文账号名拼进 URL 之后那个地址打不开。

## 五、首次推送

```bash
git push -u origin main      # -u 建立跟踪关系，之后直接 git push
```

- 有 tag 的话，tag 跟着单独推（**不要用 `--tags`**，见主文件铁律 3）。
- **首次推送时「旧 tag 零变动」那一项无从比较** —— 回验脚本此时应报**跳过**，不是通过。
  这不是缺陷，是这一项的适用范围（见主文件阶段 9）。
- 若本地是空仓库（连提交都没有），先建一个提交；**推送不存在的分支不会自动创建它**。

## 六、检查清单

- [ ] 默认分支名在第一次提交**之前**就定好了
- [ ] 远端是空仓库（`git ls-remote` 有输出就要先搞清楚原因）
- [ ] 没有为了「有个 README」而在远端造出无关提交
- [ ] 可见性、许可、主题、简介都已配上，且许可文件与门面一致
- [ ] `user.name` / `user.email` 写的是仓库级配置，邮箱是带数字 ID 的专用免回复形态
- [ ] 首次提交后回看一眼贡献记录有没有落对账号
- [ ] 首次推送用了 `-u`；tag 单独推而不是 `--tags`
- [ ] 回验时「旧 tag 零变动」一项报的是**跳过**，没有被写成通过
